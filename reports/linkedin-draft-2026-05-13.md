**Vector similarity is the wrong tool for professional documents.** The assumption that semantic closeness equals relevance breaks the moment a question requires cross-section reasoning, domain vocabulary, or multi-step retrieval over a 200-page filing.

PageIndex from VectifyAI built something different. Instead of embedding chunks, they build a hierarchical tree index first. Think table of contents, generated by an LLM that understands the document's actual structure. Each node stores a section title, a page range, and a summary.

The retrieval step hands that tree to a second LLM call. No similarity search. The model reasons over the structure to find relevant node IDs, then fetches only those pages.

The benchmark is hard to argue with. 98.7% on FinanceBench, beating every vector-based RAG system on the leaderboard.

What makes this portable is the architecture itself. You do not need their cloud service. The two-step pattern works on any corpus where structure matters more than surface similarity. Financial filings, legal contracts, technical manuals.

For n8n builders, this fits inside an AI Agent node. Index once. Retrieve on every query. The only dependency is your LLM.

The part worth studying is not the accuracy score. It is how they split indexing from retrieval and gave each step a distinct LLM call doing a fundamentally different job.
